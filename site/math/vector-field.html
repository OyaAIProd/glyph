New mark in the registry

Rotation vector field

The classic rotation field (-y, x) sampled on a 5×5 grid. Each row produces one arrow rooted at (x, y) pointing toward (x + dx, y + dy). The arrows share a single <marker> in <defs> so the SVG stays self-contained — no external assets, no client-side JS to compute arrowheads.

Spec

{
  "version": "glyph/0.1",
  "title": "Rotation field (-y, x) on a 5×5 grid",
  "data": { "source": "inline:vector-field-rotation" },
  "layers": [
    {
      "mark": "vector-field",
      "encoding": {
        "x": { "field": "x", "type": "quantitative" },
        "y": { "field": "y", "type": "quantitative" }
      }
    }
  ]
}
Data shape: rows need {x, y, dx, dy} columns. The "inline:vector-field-rotation" source is the fixture's stub; in your own spec, point data.source at a CSV/Parquet/JSON with those four columns. Math PR3's mark registry is what made adding this mark a 100-line file instead of a packaging exercise.
