# Track E — Joy of Math

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`. Each PR is one subagent dispatch. The master PR cycle template lives in `2026-05-18-tier-s-master.md`. Phase 2 coordinator: `2026-05-21-phase-2-master.md`.

**Bar raiser:** An 8–15 year old types into Claude / ChatGPT / Gemini

> *"What's a sine wave?"*

…and gets back a chart that is **beautiful**, **intuitive**, and **simple to articulate math beauty**. Tracing dot. Labeled peak. Captions that fade in as the wave draws. Slider for amplitude. Friendly colors. Whole thing generated by the agent from one natural-language prompt with no spec editing required by the kid.

Today the existing stack hits 1 of 7 things that experience requires (the draw-in animation from Track A2). This track ships the remaining 6.

**Goal:** Make Glyph the default tool an LLM agent reaches for when a kid wants to **explore and understand math through generated visualizations**.

**Architecture:** Five additive grammar extensions on top of Phase 1 + Track A. Each is one PR:
- New `mark: "annotation"` (arrow + label + bubble, anchored)
- New `mark: "traveler"` (point traversing a path over time)
- New `animation.kind: "timeline"` (sequenced scenes with captions)
- Two new built-in brand-kit presets (`playground`, `3b1b`)
- New `glyph_story` MCP verb (intent → multi-scene spec)

**Tech stack:** Same as `@glyph/core` (TypeScript strict, Zod, biome, vitest). No new runtime deps — composes M4's BrandKit, A1's trajectories, A2's draw-in, M1's provenance, M2's structured explain.

**Effort:** L (5 PRs across ~5 calendar weeks, with E5 carrying most of the surface area).

**Validation:** ship the "show me a sine wave" demo end-to-end — natural-language prompt → MCP call → animated SVG with traveling dot + fade-in captions + peak annotation + playground theme. Posted as a featured demo in `site/math/` gallery.

## PR E1 — `mark: "annotation"` (anchor + arrow + bubble)

**Branch:** `feat/track-e1-annotation-mark`

**Goal:** Give the agent vocabulary to point at chart features. An annotation is a labeled callout anchored to a data point or a fixed coordinate, with an automatic arrow and a text bubble.

**Files:**
- Create: `packages/core/src/compiler/marks/annotation.{ts,test.ts}`
- Modify: `packages/core/src/spec/schemas.ts` — add to `MarkSchema` enum + extend `LayerSchema` with annotation-specific fields under a refinement
- Modify: `packages/core/src/spec/types.ts`
- Modify: `packages/core/src/compiler/compile.ts` — register the mark + dispatch
- Modify: `packages/core/src/scenegraph/types.ts` — if needed, add SceneMark types for path-arrow + bubble
- Create: `packages/core/__fixtures__/annotation/peak-callout.{json,svg,test.ts}`

**Schema:**
```ts
{
  mark: "annotation",
  // Anchor — either a data row (by index) or a fixed (x, y) in data space.
  anchor: { kind: "data"; rowIndex: number } | { kind: "coord"; x: number; y: number },
  // The labeled text.
  text: string,
  // Arrow style. "auto" picks a side based on which edge of the chart
  // the anchor is closest to.
  arrow: "auto" | { dx: number; dy: number },  // dx/dy in data units, offset from anchor to bubble
  fontSize?: number,    // default 14
  color?: string,        // default theme.fg
  // Optional accent style — outlines the anchor point with a small ring
  // so the kid sees what the arrow is pointing to.
  highlight?: boolean,   // default true
}
```

**Composition with existing capabilities:**
- The bubble + arrow are SceneMarks → render through the existing SVG path.
- Animation: when the spec's animation kind is `"timeline"` (E3) or `"draw-in"` (A2), the annotation fades in at the right beat via a SMIL `<animate>` on `opacity`.

**Acceptance:**
- Fixture `peak-callout.json` renders a sine curve with a "peak!" annotation at x = π/2
- Snapshot test asserts byte-identity + visual presence of arrow + bubble
- Hand-verify against the screenshot: arrow points cleanly at (π/2, 1)

## PR E2 — `mark: "traveler"` (point along a path)

**Branch:** `feat/track-e2-traveler-mark`

**Goal:** A dot that traces a path mark over time. The kid-delight quick-win.

**Files:**
- Create: `packages/core/src/compiler/marks/traveler.{ts,test.ts}`
- Modify: schemas / types / compile-dispatch (same pattern as E1)
- Create: fixture `traveler/sine-traveler.{json,svg,test.ts}`

**Schema:**
```ts
{
  mark: "traveler",
  // Which path the traveler follows. Either:
  //  - a path layer by id (set `id` on the target layer)
  //  - the layer's own `path` (the same path the traveler is inside)
  follow: { layerId: string } | "self",
  // Animation duration (re-used from animation block; default matches
  // the chart's animation.duration_ms).
  duration_ms?: number,
  // Optional trailing tail — a fading line behind the traveler's head.
  trail?: {
    length: number;     // fraction of total path, 0..1 (default 0.15)
    fade: boolean;      // default true
  },
  // Size of the traveling dot.
  radius?: number,      // default 4
  color?: string,       // default theme.marks[0]
}
```

**Mechanism:**
- At compile time: sample the followed path's polyline into N evenly-spaced points (using `polylineLength` from A2 + arc-length parameterization).
- Emit one `<circle>` SceneMark per frame, or use a SMIL `<animateMotion>` with `mpath` pointing at the target path's id.
- `animateMotion` keeps the SVG self-contained + deterministic.

**Composition:**
- Works with `mark: "line"` paths (including parametric and trajectory data)
- Works with `animation.kind: "draw-in"` — the traveler appears at the head of the drawing wave
- Works with `timeline` (E3) — the traveler can be sequenced into a specific scene

**Acceptance:**
- Fixture `sine-traveler.json` renders a sine wave + a traveling dot tracing it over 4 seconds
- The dot starts at (-2π, sin(-2π)=0) and ends at (2π, 0), passing through each peak / trough
- Snapshot test asserts the `<animateMotion>` element is present + the `mpath xlink:href` references the target line's id

## PR E3 — `animation.kind: "timeline"` (sequenced scenes + captions)

**Branch:** `feat/track-e3-timeline-animation`

**Goal:** Multi-step narrative pacing. The architectural piece that lets a single spec describe "first draw the circle, then mark the point, then show the angle…"

**Files:**
- Modify: `packages/core/src/spec/schemas.ts` — extend animation discriminated union with `kind: "timeline"`
- Modify: `packages/core/src/render/svg.ts` — emit per-scene `<animate>` blocks with staggered `begin` times
- Create: `packages/core/__fixtures__/timeline/circle-circumference.{json,svg,test.ts}`

**Schema:**
```ts
{
  animation: {
    kind: "timeline",
    scenes: [
      {
        // ID for cross-references (used by E1 annotations + E2 travelers).
        id: string,
        // When this scene becomes visible relative to the chart start.
        begin_ms: number,
        // Duration the scene's marks fade in / draw in over.
        duration_ms: number,
        // Which layer indexes the scene contains. Other layers are hidden
        // until their scene fires.
        layers: number[],
        // Optional caption rendered at the bottom of the chart.
        caption?: string,
      },
      ...
    ],
  },
}
```

**Mechanism:**
- Compiler emits one `SceneMark` per layer with a SMIL `opacity` animation:
  `<animate attributeName="opacity" from="0" to="1" begin="<begin_ms>ms" dur="500ms" fill="freeze">`.
- Captions: emit a single `<text>` element with `<animate>` animating both opacity (fade in) and `y` (slight rise from below).
- `draw-in` animations (A2) inside a scene auto-derive their `begin_ms` from the scene's `begin_ms`.

**Composition:**
- E1 annotations carry an optional `scene` field that, when set, gates their fade-in on that scene's beat.
- E2 travelers similarly.
- E4 brand-kit presets apply to the timeline as a whole.

**Acceptance:**
- Fixture `circle-circumference.json` renders a 3-scene story:
  - Scene 1 (0–2s): draw a unit circle
  - Scene 2 (2–4s): mark a point on it + annotate "this is the radius"
  - Scene 3 (4–6s): show the circumference unwrapping into a line of length 2π
- Each scene has a caption that fades in
- Snapshot byte-identity across re-renders

## PR E5 — `glyph_story` MCP verb (the bar-raiser endpoint)

**Branch:** `feat/track-e5-glyph-story`

**Goal:** A new MCP verb that takes natural-language intent and returns a multi-scene Glyph spec ready to render. This is what an LLM agent actually wraps to deliver the bar-raiser experience.

**Files:**
- Create: `packages/core/src/story/compose.{ts,test.ts}` — pure-fn composer
- Modify: `packages/mcp/src/server.ts` — register `glyph_story` verb
- Modify: `packages/mcp/src/server.test.ts` — handler tests
- Create: `packages/core/__fixtures__/story/sine-wave-for-an-8yo.{json,svg,test.ts}` — end-to-end
- Update: `site/math/joy/sine-for-an-8yo.html` — the marketing demo

**Verb signature:**
```ts
glyph_story({
  intent: string,                           // "show me a sine wave for an 8-year-old"
  audience?: "kid" | "high-school" | "adult", // default "kid"
  theme?: string,                            // default "playground"
  duration_ms?: number,                      // default 8000
}) → {
  spec: GlyphSpec;                           // multi-scene timeline + annotations + traveler
  explanation: Explanation;                  // (from M2) — structured pre-built narration
  caption_sequence: Array<{ scene: string; text: string; at_ms: number }>;
}
```

**Composer logic (pure-fn, no LLM):**
- Parse `intent` for known math concepts ("sine wave", "circle", "parabola", "vector field", etc.) via a registry of patterns
- For each match, look up a canonical recipe:
  - Sine wave: `data.shape: "function", expr: "sin(x)"` + a 3-scene timeline (draw the curve, traveling dot, peak/trough annotations)
  - Circle/π: trajectory data + 3 scenes (draw circle, mark radius, unwrap to 2πr)
  - Parabola: scalar function `expr: "x*x"` + 2 scenes (draw + label vertex)
- Apply audience-specific defaults: kid → playground theme, larger fonts, simpler captions
- Return the composed spec + a pre-built structured explanation

**No-match handling:**
- When the intent doesn't match a known recipe, return an empty spec + an `Explanation` whose `suggestedFollowups` lists the known recipes the agent can try

**Composition with everything else:**
- The returned spec embeds: M4 BrandKit (E4 preset) + M1 provenance seal + M2-friendly structured explanation
- The renderer applies E1 annotations + E2 travelers + E3 timeline + A2 draw-in
- Output is a self-contained SVG with SMIL animation — works in any browser, no JS runtime

**Acceptance:**
- Fixture `sine-wave-for-an-8yo.json` is the output of `glyph_story({intent: "show me a sine wave", audience: "kid"})`
- The fixture renders the full bar-raiser demo: sine curve drawing in over 2s with playground theme, traveling dot, "peak!" annotation, fade-in captions
- Snapshot byte-identity
- 5+ recipes registered (sine, cosine, circle, parabola, vector field)

## Validation gates

### Gate 1 — After E1 + E2 ship (end of Round 12)

**Pass condition:** A hand-authored spec that uses `mark: "annotation"` + `mark: "traveler"` + `animation.kind: "draw-in"` together renders correctly. Test by combining the 3 fixtures into one composite layout in the math gallery.

**Fail condition:** The 3 capabilities don't compose (annotations don't fade in alongside draw-in, traveler doesn't run at the same time as draw-in, etc.). Stop. Revisit the animation orchestration model before shipping E3.

### Gate 2 — After E5 ships (end of Round 14)

**Pass condition:** A literal kid-aged tester (8-15) reads the prompt response on a tablet and can articulate what the math concept means within 30 seconds, without scrolling text or pinch-zooming.

**Fail condition:** They can't. Iterate on E4 (theme) + E5 (recipe library) before claiming the bar.

This is a human-in-the-loop gate, not a CI gate. Schedule it explicitly with whoever knows an 8-15 year old.

## Risk register

| Risk | Mitigation |
|------|------------|
| `mark: "annotation"` clashes with the existing math-text mark | Annotation = arrow + bubble + auto-layout; math-text = LaTeX text at a fixed coord. Distinct enough to coexist. |
| `mark: "traveler"` SMIL `animateMotion` is buggy in some renderers | Test in Chromium + Firefox + WebKit; fall back to discrete `<circle>` per frame on failure (slightly larger SVG, same visual). |
| `animation.kind: "timeline"` makes the SVG huge for long sequences | Cap total scene count at 10 in the schema. Beyond that, the agent should produce a story page (multiple separate charts) rather than one mega-scene. |
| The `glyph_story` recipe library doesn't cover what kids ask for | Ship 5 recipes in E5; track agent-side prompts that miss; add quarterly. |
| Brand presets fall out of fashion | Both `"playground"` and `"3b1b"` are versioned via the BrandKit's `format: "glyph-brand/1"`. A future `"glyph-brand/2"` can ship updated presets. |
| Performance: per-scene `<animate>` blocks balloon DOM size | Browser SMIL handles 100s of simultaneous animations fine; if it ever becomes an issue, an optional `compileAnimationsToCss: true` flag flattens to CSS keyframes. |
